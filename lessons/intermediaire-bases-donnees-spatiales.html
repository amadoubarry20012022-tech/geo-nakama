Les bases de données spatiales

Derrière chaque carte se cache une table. Savoir l'interroger et la relier à d'autres tables est la clé de toute analyse en SIG.

Objectifs de cette leçon

  • Expliquer qu'une donnée spatiale associe une géométrie à des attributs.
  • Lire une table d'attributs et formuler une requête de sélection.
  • Comprendre une jointure, et la différence avec une jointure spatiale.

Une géométrie et des attributs

Dans un SIG, chaque objet de la carte possède deux sortes d'informations :

  • sa géométrie : où il se trouve et quelle forme il a (point, ligne, polygone) ;
  • ses attributs : ce qu'il est (un nom, un type, un nombre de lits, une date…).

Les attributs forment une table : une ligne par objet, une colonne par caractéristique. Chaque ligne est reliée à sa géométrie par un identifiant unique. Cliquer sur un objet de la carte revient donc à lire une ligne de la table, et inversement.

Chaque colonne a un type : texte, nombre entier, nombre décimal, date, oui/non. Ce type compte, car on ne compare pas du texte comme on compare des nombres. Cette table est stockée avec la géométrie dans un fichier (shapefile, GeoPackage) ou dans une base de données spatiale comme PostGIS.

Parler à la base : le SQL

        
La ligne sombre sous vos menus est une requête SQL, le langage des bases de données. Elle se lit presque comme une phrase :

        
SELECT * FROM centres WHERE lits > 50;

        
« Sélectionner toutes les colonnes de la table centres, là où le nombre de lits dépasse 50. » On peut combiner plusieurs conditions avec AND (les deux vraies) ou OR (l'une ou l'autre).

        
Dans une base spatiale comme PostGIS, SQL gagne des fonctions qui comprennent la géométrie : par exemple, ST_DWithin sélectionne les objets situés à moins d'une certaine distance d'un autre. C'est ce qu'on appelle une requête spatiale.

      


      
      

        
Relier deux tables : la jointure

        
Les données sont souvent réparties dans plusieurs tables. Ici, la table des centres ne dit rien de la population de leur région, qui se trouve dans une autre table. Pour les réunir, on fait une jointure : on relie les lignes qui partagent la même valeur dans une colonne commune, ici le code de région.


        

          

            

              

                

                  Table « centres » (extrait)
                  
nomrégion

                  
                

              

            

            

              

                

                  Table « regions »
                  
codenom_regionpopulation

                  
                

              

            

          


          


          

            
SELECT c.nom, c.region, r.nom_region, r.population
FROM centres c
JOIN regions r ON c.region = r.code;

            

              

                Résultat de la jointure
                
                  
nomrégionnom_regionpopulation

                
                
              

            

            
Chaque centre a récupéré les informations de sa région. La population est une donnée fictive.

          

        


        

          Jointure attributaire ou jointure spatiale ? Celle-ci s'appuie sur une colonne commune. Une jointure spatiale relie au contraire les objets d'après leur position : par exemple, associer à chaque centre la région dans laquelle il se trouve, même sans code commun. Elle utilise la géométrie, pas un identifiant.
        

      


      
      

        
À retenir

        
    
          
  • Un objet spatial = une géométrie + une ligne de la table d'attributs, reliées par un identifiant.
    • 
          
  • Une requête filtre les lignes d'après une colonne, un opérateur et une valeur : en SQL, SELECT … WHERE ….
    • 
          
  • Une jointure relie deux tables par une colonne commune ; une jointure spatiale les relie par la position.
